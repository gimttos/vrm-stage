# VRM Stage

> VRM을 올리면 방송 화면이 완성되는 사이트.
> OBS 브라우저 소스 URL 하나, 씬은 링크로 공유, 트래커는 쓰던 걸 그대로.

설계 배경과 차별화 논지는 [docs/PRODUCT.md](docs/PRODUCT.md)에 있습니다.

## 실행

```bash
npm install
npm run dev
```

http://localhost:5173 을 엽니다. VRM 파일을 창에 드래그하거나, 패널에서 번들된
픽스처(`tttt.vrm` = VRM 1.0, `reee.vrm` = VRM 0.x) 중 하나를 누르면 됩니다.

파일은 **업로드되지 않습니다** — 브라우저 안에서만 열립니다.
(방송 룸을 쓸 때만 예외입니다. 시청자가 아바타를 직접 렌더하므로 그때는 모델이
R2로 올라갑니다.)

방송 룸을 쓰려면 Worker도 같이 띄웁니다 — 개발 서버가 `/api`를 여기로 프록시합니다:

```bash
npm run serve
```

## 화면 구성

- **Ctrl + 드래그** — 아바타 위치 이동
- **휠** — 확대·축소
- **시야 초기화** 버튼 — 기본 프레이밍으로 복귀

프레이밍은 모델의 **머리–엉덩이 길이**를 스케일 기준으로 삼아 화각에서 거리를
역산합니다. 고정 거리를 쓰면 평균 체형이 아닌 모델에서 정수리가 잘리기 때문입니다
(흉상 기준 프레임 반높이 `1.15 × tan(14°) ≈ 0.287` 인데 정수리가 `0.30` 이라 실제로
잘리고 있었습니다). 조정한 위치·줌은 OBS URL에 함께 실립니다.

## 손 트래킹 (웹캠)

`HandLandmarker`를 얼굴 검출기와 같은 비디오·같은 루프에서 돌립니다.
**GPU 비용이 대략 두 배**가 되므로 패널에서 끌 수 있습니다.

- **손가락** — 21개 랜드마크의 관절 굴곡을 측정해 손가락 본에 넣습니다. 각도는
  왜곡 없는 metric world 랜드마크로, 화면 위치는 정규화 랜드마크로 계산합니다
  (정규화 좌표로 각도를 재면 카메라 종횡비가 모든 관절에 섞여 들어갑니다).
- **팔** — 폴 벡터 2본 해석적 IK. 팔꿈치가 접히는 평면을 폴 벡터(아래·바깥·약간
  뒤 — 인간 팔꿈치의 자연 위치)가 고정하므로 부호 추측이 없고, 겨냥+비틀림
  모호성으로 어깨가 등 뒤로 꺾이던 문제가 구조적으로 사라졌습니다. 리치는 완전
  신전·완전 접힘 특이점 바깥으로 클램프됩니다 (검증: IK 오차 ≤0.074, 통상 0.021).
- **손목** — 랜드마크에서 손바닥 기저(손가락 방향 × 손바닥 법선)를 만들어 손목
  본에 겁니다. 축 매핑이 틀린 환경이면 `손목 회전` 토글로 끄세요.
- **손 위치는 얼굴 기준** — 절대 화면좌표가 아니라 "얼굴에서 얼굴폭 몇 개 거리"로
  잡습니다. 카메라 배치·프레이밍이 바뀌어도 같은 곳을 가리키고, 얼굴이 안 보이면
  팔은 멈춥니다(엉뚱한 곳으로 가느니 정지가 낫습니다).
- **전방 반구 클램프** — 팔 겨냥 방향이 몸통 평면을 넘지 못하게 막습니다. 웹캠은
  손의 앞뒤를 모르므로, 트래커가 뭐라 하든 어깨가 등 뒤로 꺾이는 것은 기하적으로
  불가능하게 만들었습니다.

VMC 입력일 때는 **보내는 쪽 리그가 이미 팔과 손가락을 포함**하므로 웹캠 손 트래킹은
자동으로 비활성화됩니다 (덮어쓰면 손해).

### 조정 손잡이

방향이 반대로 나오면 패널에서 뒤집으세요 — 좌표 규약은 실물로 한 번 확인하는 게
가장 빠릅니다.

| 증상 | 토글 |
|---|---|
| 손가락이 손등 쪽으로 젖혀짐 | 손가락 굽힘 반전 |
| 손목이 이상하게 돌아감 | 손목 회전 끄기 |
| 팔이 너무 좁게/넓게 움직임 | 팔 이동 범위 |
| 팔을 올리면 내려감 | 팔 상하 반전 |
| 팔을 앞으로 뻗으면 뒤로 감 | 팔 앞뒤 반전 |
| 팔이 반대쪽으로 감 (거울과 별개로) | 팔 좌우 반전 |
| 시선이 반대로 감 | 시선 반전 (트래킹 탭) |
| 상체가 반대로 기욺 | 상체 좌우 반전 |
| 고개 방향이 반대 | Pitch / Yaw / Roll 반전 (보정 탭) |

**모든 반전 토글은 꺼진 상태가 기본이고, 그 상태가 올바릅니다.** VRM 0.x와 1.0이
동일하게 동작하도록 맞춰져 있으니 규격 때문에 켤 필요는 없습니다. 토글은 순수하게
"내 웹캠·드라이버가 특이할 때"를 위한 탈출구입니다.

머리의 `Pitch/Yaw/Roll 반전`과 같은 성격입니다. 내부 매핑은 검증돼 있지만
(얼굴 위의 손 → 아바타 손도 위, 카메라에 가까운 손 → 앞으로), **어떤 웹캠·드라이버가
"위"와 "가까움"을 어떤 부호로 보고하는지는 코드가 알 수 없습니다.** 세로로 뒤집힌
피드나 손바닥 단축(foreshortening)이 이를 반전시킵니다 — 한 번 보고 맞추는 게
가장 빠릅니다.

(`팔꿈치 반전`은 삭제 — 폴 벡터 IK는 팔꿈치 방향을 추측하지 않으므로 필요 없어졌습니다.)

## 감정 단축키

숫자키 **1–6**으로 프리셋 표정 토글(무표정·기쁨·화남·슬픔·편안·놀람), **0/Esc** 해제.
같은 키를 다시 누르면 풀립니다. 편집 탭에서 누른 감정은 **BroadcastChannel**로 열려
있는 OBS 브라우저소스 인스턴스에 실시간 반영됩니다 — 두 탭은 별개 페이지라 이 채널이
없으면 단축키가 방송 화면에 닿지 않습니다.

엄지는 손바닥으로 굽는 게 아니라 대립하는 관절이라 축이 다릅니다.
`src/driver/handRig.ts` 에서 가장 손볼 가능성이 높은 부분입니다.

## 씬 (P1)

배경 + 오버레이가 아바타와 **같은 프레임 안의 한 문서**입니다. StreamElements
브라우저소스 N개 대신 씬 하나.

- **배경**: 투명(기본) / 색상 / 이미지
- **텍스트 오버레이**: 크기·색·굵기·그림자, 드래그로 배치
- **이미지 오버레이**: 로컬 파일(300KB 이하, data URL로 씬에 내장) — 드래그 배치, 너비 조절
- 클릭 선택 → 패널 하단 인스펙터에서 편집, **Delete** 삭제, **Esc** 선택 해제
- **씬 링크 복사**: 씬 전체가 URL 해시(`#s=…`)에 담깁니다. 누구에게나 그대로 열림
- 내보내기/가져오기: `.json` 파일
- 편집 탭 ↔ 같은 브라우저의 다른 탭은 BroadcastChannel로 실시간 동기화

### 실제 OBS에 관한 정직한 주의

OBS 브라우저소스는 **OBS 내장 CEF — 별도 브라우저**입니다. 크롬과 localStorage·
IndexedDB·BroadcastChannel을 공유하지 않습니다. 그래서:

- **씬은 URL 해시에 자체 포함**되므로 실제 OBS에서 그대로 재현됩니다 (저장소가
  빈 상태에서 해시만으로 재현되는 것을 검증함).
- **`?model=idb:last`는 실제 OBS에서는 통하지 않습니다** (OBS의 IndexedDB는 비어
  있음). 실제 OBS용으로는 모델 파일을 서빙 경로에 두세요: `public/models/foo.vrm`
  → `?model=/models/foo.vrm`.
- 편집 탭 → 실제 OBS로의 **실시간 동기화**(감정·씬)는 아직 안 됩니다. P2에서
  브리지에 WebSocket 릴레이를 얹어 해결할 계획입니다. 지금은 씬을 바꾸면 OBS URL을
  다시 복사해 붙이는 방식입니다.

## VMC 입력 (VSeeFace · VNyan · Warudo)

이미 쓰는 트래커를 그대로 쓰고, 화면 합성만 여기서 하는 경로입니다.

**브라우저는 UDP를 받을 수 없고 VMC는 OSC over UDP이므로 로컬 브리지가 필요합니다.**
이게 "설치 0"에 붙는 유일한 단서입니다. 다만 VMC를 보내는 사람은 이미 데스크톱
소프트웨어를 돌리는 중이라 프로세스 하나 추가는 부담이 아닙니다.

```
VSeeFace  --OSC/UDP 39539-->  bridge  --WebSocket 39541-->  브라우저
```

```bash
npm run bridge     # 별도 터미널
npm run dev
```

그 다음 패널 → 트래킹 → 입력을 **VMC**로. VSeeFace 쪽은
`Settings > General > VMC protocol sender` 를 켜고 `127.0.0.1:39539` 로 보냅니다.

**VSeeFace 없이 시험하려면:**

```bash
npm run bridge
npm run bridge:test   # 합성 VMC 송신 — 고개를 좌우로 젓고 손가락을 굽힙니다
```

VMC가 붙으면 아바타는 **전신 리그를 그대로 받습니다** — 팔, 손가락, 이미 튜닝된
솔브까지. 웹캠으로는 못 하는 부분이고, 이때 드라이버는 자체 블렌드셰이프 추정을
버리고 리그를 우선합니다 (디버그 패널의 `rig source` 에 본 개수가 표시됩니다).

### 알려진 미확인 사항

**핸디드니스 변환은 실제 송신기로 확인해야 합니다.** VMC 송신기는 Unity 앱이라
좌표계가 왼손이고, 회전을 `(x, -y, -z, w)` 로 미러링해 넣고 있습니다. 표준 변환이지만
합성 송신기로는 검증할 수 없습니다(같은 가정을 되돌려받을 뿐). **팔이나 고개가
반대로 움직이면** `src/tracking/VMCSource.ts` 의 `convertHandedness` 를 뒤집으세요.

Unity `HumanBodyBones` → VRM 본 이름 매핑은 실제 모델로 검증했습니다 (55개 중 54개
적중, `Jaw` 만 미스 — VRoid가 내보내지 않음). 엄지는 특히 주의가 필요한 지점입니다:
Unity는 Proximal/Intermediate/Distal, VRM 1.0은 Metacarpal/Proximal/Distal로 세 관절을
부르기 때문에 단순 소문자화하면 엄지가 **엉뚱한 관절에서 굽고 한 관절은 아예
누락됩니다.** `src/tracking/unityBones.ts` 에서 명시적으로 교정합니다.

## 중립 자세 보정

웹캠이 눈높이보다 낮으면 얼굴을 아래에서 올려다보게 되어 **고개가 계속 들린
상태로 잡힙니다.** 앉은키가 클수록 심해집니다.

패널 → 중립 자세 → **지금 자세를 정면으로**. 편한 자세로 정면을 본 상태에서
누르면 그 자세가 0이 됩니다. 카메라 위치·앉은키·자세가 한 번에 해결됩니다.
미세조정 슬라이더로 추가 보정할 수 있고, 보정값은 OBS URL에 함께 실립니다.

## OBS 연결

1. 패널의 **브라우저 소스 URL 복사**
2. OBS → 소스 추가 → **브라우저**
3. URL 붙여넣기, 너비/높이를 캔버스에 맞춤

`?obs=1`이 붙으면 UI가 숨고 배경이 투명해집니다. 크로마키도, 윈도우 캡처도
필요 없습니다 — 이게 데스크톱 툴 대비 첫 번째 차별점입니다.

복사되는 URL에는 **현재 모델과 보정값이 포함됩니다.** 드래그로 넣은 로컬 파일은
URL로 표현할 수 없으므로 IndexedDB에 캐시되고 `?model=idb:last`로 참조됩니다
(업로드가 아니라 브라우저 자체 저장소입니다). 이게 빠져 있으면 OBS에서 투명한
빈 화면만 뜹니다.

URL 파라미터:

| 파라미터 | 예 | 뜻 |
|---|---|---|
| `mode` | `studio` \| `live` \| `rig` | 어떤 화면인지 (기본 `studio`) |
| `room` | `cpdeixyrup` | 방송 룸 구독 (`source=remote`와 함께) |
| `track` | `0` | 이 창에서 트래킹을 하지 않음 |
| `obs` | `1` | `mode=live`의 영구 별칭 |
| `framing` | `bust` \| `head` \| `full` | 카메라 프레이밍 |
| `model` | `/fixtures/tttt.vrm`, `idb:last` | 시작 시 자동 로드 |
| `credit` | `0` | 라이선스 오버레이 숨김 |
| `pitch` `yaw` `roll` | `-0.1745` | 중립 자세 보정값 (라디안) |
| `source` | `webcam` \| `vmc` \| `remote` | 트래킹 입력 |
| `px` `py` `zoom` | `0.12` `-0.05` `1.4` | 조정한 화면 위치·줌 |
| `mp` | `cdn` | MediaPipe 애셋을 CDN에서 (디버깅용) |

## 방송 룸 — 링크를 연 모두가 호스트의 움직임을 봅니다

방송이란 **연기하는 사람의 몸이 아바타를 움직이고 나머지는 그것을 본다**는 뜻입니다.
링크를 연 사람이 각자 자기 웹캠으로 아바타를 조종한다면 그건 방송이 아니라 공유된
장난감입니다. 룸은 그 비대칭을 만듭니다.

```
studio 탭 (카메라) ──발행──> 룸 ──구독──> OBS 브라우저 소스 ──> Twitch/YouTube
                              └──구독──> 원격 시청자
```

**OBS도 구독자입니다.** 그래서 카메라를 쓰는 창은 studio 탭 하나뿐이고,
OBS와 원격 시청자는 **완전히 같은 링크**를 씁니다.

패널 → 출력 → **방송 시작** → **시청 링크 복사**.

### 왜 영상이 아니라 데이터를 보내는가

프레임 하나가 **208바이트**입니다 — 리그가 실제로 읽는 값만 담습니다 (블렌드셰이프
18개, 머리 3축, 양손의 굽힘·펼침·얼굴 상대 위치·팔 기저). 30fps에 **시청자당 6.2KB/s**로,
영상 대비 자릿수가 다릅니다. 인코더도, TURN도, SFU도 필요 없습니다.

시청자 브라우저가 아바타를 직접 렌더하므로 **VRM 파일이 시청자에게 전달됩니다**
(R2에 올라가고 룸이 그 URL을 알려줍니다). 모델이 나가면 안 되는 상황이라면 이 방식은
맞지 않고, 영상 송출이 답입니다.

### 모델은 방송이 끝나면 지워집니다

**방송 정지**를 누르면 올렸던 모델이 R2에서 삭제됩니다. 호스트가 탭을 닫아버린 경우에도
룸 TTL 알람이 같은 정리를 합니다. 저장 비용 때문이 아니라 — 15MB 하나는 무료 한도
10GB의 0.15%입니다 — **저자 전용 모델이 방송이 끝난 뒤에도 공개 URL로 남아 있지 않게**
하려는 것입니다.

삭제는 서버가 합니다. 룸이 R2 키와 호스트 키를 모두 갖고 있으므로, 시청자는 남의 방송을
끝낼 수 없고(403), 조작된 `model` 메시지로 엉뚱한 객체를 지우게 만들 수도 없습니다
(Worker가 만든 URL 형태만 삭제 대상이 됩니다). 정지 후 다시 방송하면 모델을 새로
올립니다.

### 비용

현재 설계는 **Cloudflare 무료 한도 안**입니다.

| | 무료 한도 | 이 앱의 사용량 |
|---|---|---|
| R2 저장 | 10 GB-month (만료 없음) | 모델 1개 = 0.015 GB |
| R2 쓰기 / 읽기 | 100만 / 1000만 per month | 방송당 1건 / 시청자당 1건 |
| R2 이그레스 | 항상 무료 | — |
| DO 요청 | 100,000/일 | 발행 10 msg/s → **20:1 과금** → 시간당 1,800건 |
| DO duration | 13,000 GB-s/일 | Hibernation API라 실행 시간만 과금 |

Durable Objects는 **무료 플랜에서 SQLite 백엔드로 동작**하고, `wrangler.jsonc`의
`new_sqlite_classes`가 그 설정입니다. 수신 WebSocket 메시지가 20:1로 과금되는 덕에
하루 50시간 넘게 방송해도 요청 한도에 닿지 않습니다.

### 시청자는 아바타를 조종할 수 없습니다

역할은 **서버가** 강제합니다 — URL에 적힌 역할이 아니라 Durable Object가 가진
`hostKey`로 판정하고, 구독자가 보낸 것은 무엇이든 버립니다. 클라이언트 측 강제는
연극이라는 것을 크레딧 표시에서 이미 겪었으므로, 같은 실수를 반복하지 않습니다.

시청자 페이지는 애초에 `WebcamSource`를 만들지 않으므로 카메라를 열 코드 경로 자체가
없습니다. 즉 읽기 전용이 구조적이고, 서버가 한 번 더 막습니다.

검증: `npm run room:test` (19개 검사, 그중 하나가 "subscriber frames reach NOBODY"),
`node scripts/room-publish-demo.mjs` (카메라 없이 합성 호스트로 시청자 경로 확인).

## 모드

| 모드 | 무엇인가 | 패널 탭 |
|---|---|---|
| `studio` | 씬을 구성하는 곳. 기본값 | 씬 · 아바타 · 트래킹 · 손 · 보정 · 출력 |
| `live` | OBS 브라우저 소스에 넣는 출력. UI 없음, 투명 배경, 씬 편집 불가 | (없음) |
| `rig` | 리깅 벤치. 숫자 디버그 그리드가 여기에만 있음 | 트래킹 · 손 · 보정 · 디버그 · 아바타 |

패널이 리깅 보정 벤치와 씬 컴포지터라는 **두 개의 제품**으로 자라 있었기 때문에
나눴습니다. `?obs=1`은 이미 OBS에 붙여넣어진 URL을 위해 `mode=live`의 별칭으로
영구히 남습니다.

**카메라는 한 번에 한 창만 씁니다.** 편집 탭과 OBS 소스를 함께 열어둘 때는 한쪽에서
「이 창에서 트래킹 실행」을 끄세요 — 끄면 복사되는 라이브 URL에 `track=0`으로
따라갑니다. 경합이 생기면 그렇게 안내하는 에러가 뜹니다.

│  ├─ handRig.ts         손가락 본 + 팔 겨냥·접기

왔는지 아무도 모릅니다. 트래커를 추가하는 일은 **어댑터 하나를 추가하는 일**이고
아바타 코드는 건드리지 않습니다.

## 배포

100% 정적 사이트라 서버가 필요 없습니다. Cloudflare Pages 기준:

```bash
npx wrangler login   # 최초 1회 (브라우저 OAuth)
npm run deploy       # 빌드 → Pages 업로드
```

자세한 내용은 **[docs/SELF-HOSTING.md](docs/SELF-HOSTING.md)** 를 보세요.

- **런타임에 CDN을 타지 않습니다.** MediaPipe WASM은 `vite.config.ts`의 플러그인이
  `node_modules`에서 빌드에 내보내고, `.task` 모델은 `scripts/fetch-models.mjs`가
  SHA-256 핀과 함께 받아옵니다 (`predev`/`prebuild`가 자동 실행). `dist`는 약 39MB.
- 서브패스 호스팅: `VITE_BASE=/vrm/ npm run build`.
- 배포 사이트는 HTTPS → 웹캠(getUserMedia) 정상 동작.
- **VMC 브리지는 여전히 로컬**입니다 (VSeeFace 옆에서 돌아야 하므로 호스팅과 무관).
  HTTPS 페이지에서 `ws://127.0.0.1`은 Chrome이 localhost를 신뢰 오리진으로 취급해
  허용됩니다. `ws`는 `dependencies`에 있으므로 `npm ci --omit=dev`로도 동작합니다.
- 디버깅용 탈출구 `?mp=cdn`이 있지만 방송에는 쓰지 마세요 — CDN 장애가 방송 장애가
  됩니다.

## 픽스처 라이선스

`fixtures/`의 두 파일은 **저자 전용 · 비상업 · 개변 금지**로 표시되어 있습니다.
저자 본인의 개발용 회귀 픽스처이며 재배포 대상이 아닙니다.

`public/` **밖에** 두고 gitignore하며, 개발 중에만 `vrm-stage:dev-fixtures` 플러그인이
서브합니다. 추가로 `vrm-stage:assert-no-models` 플러그인이 `dist`에서 `.vrm`을 찾으면
빌드를 실패시킵니다. 즉 배포에 섞여 들어가는 것이 **구조적으로 불가능**합니다.
(예전에는 `postbuild`의 조용한 `rm -rf`가 유일한 장치였는데, 디렉터리 이름이 바뀌거나
`npx vite build`를 직접 돌리면 아무 경고 없이 배포됐습니다.)
